## 🔥 BOTTLENECKS
1. `PRF-001` — `MEASURED / HIGH`: `dist` is `5.599 MB`, almost entirely large JPEG assets. Referenced shipping images include `hero.jpg` `1.01 MB`, `fitness.jpg` `0.90 MB`, `gallery-lounge.jpg` `0.84 MB`, `restaurant.jpg` `0.82 MB`, and two avatars around `0.7-0.8 MB`. This is acceptable on localhost but risky for real mobile networks.
2. `PRF-002` — `MEASURED / MEDIUM`: runtime depends on external render-path resources. After repair, slowest resource timings still show Google Fonts around `134-175 ms`, Tailwind CDN around `122-130 ms`, and NBRB fetch around `72-99 ms` in lab. For a public portfolio demo this is tolerable; for production, local compiled CSS and font strategy would be the next perf step.
3. `PRF-004` — `MEASURED / MEDIUM`: mobile CLS is still below threshold but close: `0.0978 / 0.1`. Any later hero/font/layout change can push it into fail.

## Perf Summary
- **Perf status:** local performance is good; public-network performance is likely limited by asset weight and CDN runtime dependencies.
- **Главная измеренная проблема:** `5.599 MB` static artifact with large JPEGs.
- **Главный reliability-риск:** runtime styling/fonts depend on third-party CDNs.
- **Главный следующий шаг:** optimize representative images with a real image pipeline (`WebP/AVIF`, responsive sizes) and replace Tailwind CDN with built CSS if the project should be judged as a polished public repo rather than a quick demo.

## 🛠️ TOP FIXES
1. `HIGH`: Add an image optimization pipeline for referenced assets. Target: hero/interior/media images below practical responsive sizes, with `WebP/AVIF` variants and fallbacks. Do this with a real tool (`sharp`, `squoosh`, `imagemin`, Cloudflare/Vercel image pipeline), not manual binary guessing.
2. `MEDIUM`: Replace Tailwind CDN with compiled CSS for the static artifact. This removes a runtime script dependency and makes styling deterministic.
3. `MEDIUM`: Keep mobile CLS under watch; add a perf assertion or Playwright metric check for `CLS < 0.1` after future hero/font changes.
4. `LOW`: Add field Web Vitals collection only if this becomes a real public site with traffic.
